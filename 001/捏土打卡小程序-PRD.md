## 一、产品背景与定位

### 1.1 背景

粘土（软陶 / 超轻粘土 / 树脂粘土）手作是一件「过程耗时、需要被看见」的爱好。用户在每天完成捏制后，普遍存在以下痛点：

1. **成果不可见**：作品捏完放在架子上，几个月后完全记不清哪天做的、做了多少个，做过哪些造型。
2. **缺乏坚持的反馈**：纯靠自觉打卡，容易断更；没有一个「累计数字」来证明自己的坚持。
3. **库存与营收无账本**：出了多少个、卖出多少、卖了多少钱，混杂在微信聊天记录里，无法算清单件成本与利润。
4. **分类不统一**：`OB11娃头`、`QQ人`、`正比` 是用户日常使用的三个造型分类口径，但没有统一记录的地方，年度统计时无法分类聚合。
5. **数据只在一部手机上**：清缓存、换机、重装小程序都会让几年的记录归零。没有账号就没有备份，作品记录这件有情感价值的事就只是易碎品。

### 1.2 产品定位

一款**以「每日捏制打卡」为核心动作、以「图片 + 数量」为记录载体、以「年度产量与营收统计」为价值出口**的轻量手作记录小程序。

**一句话定位**：*每天捏几个、捏了什么、拍张照，一年后你有一本自己的手作年鉴。*

### 1.3 产品目标

| 维度 | 目标 |
| --- | --- |
| 用户价值 | 让每一次手作都被记录、被看见、可量化 |
| 商业价值 | 沉淀手作人群，验证「手作周边 + 作品社交」的商业化可能 |
| 差异点 | 不做泛手工社区，只做「捏土创作者」的专业生产记录工具 |
| 留存价值 | 账号体系让几年的记录跨设备存活，作品记录不因换手机而清零 |

### 1.4 非目标（本期明确不做）

- 不做商城 / 交易闭环（只记录售出与金额，不在站内收款）
- 不做课程教学、教程内容
- 不做陌生人私信、关注流
- 不做多角色 / 工作室协同（本期仅个人单账号）
- 不做 AI 生成或图片美化
- 不做手机号注册、实名认证、密码找回——账号完全由微信身份派生，不采集手机号
- 不做第三方登录（Apple / 微博 / 抖音等）——微信小程序内只有微信身份有意义

## 二、目标用户

### 2.1 核心用户画像

> **小陶（女，26岁，手作爱好者）**
> 每周末花 3–5 小时捏粘土，主要做 `OB11娃头`、`QQ人`、`正比` 三种造型。会在小红书发作品、也偶尔在小红书挂闲鱼卖。做这个 App 的动机：「想看看今年到底做了多少个，也想把卖出去的钱记清楚。」

### 2.2 用户特征

- 手作物料是低成本、可批量制作的（单个成本 3–15 元）
- 产量节奏不规律：一开始爆发式做（赶单），后面零散做
- 拍摄习惯：作品摆拍 + 拍照打卡，是留存的关键动作
- 对「年度数据」有天然的仪式感需求（类似手账、年度报告）

### 2.3 用户核心诉求排序

1. 记录得快（≤15 秒完成一次打卡）
2. 图片好看、分类清楚、以后翻得到
3. 年度统计一眼看到「我做了多少」
4. 卖出去了要把钱记上，知道赚了多少

## 五、功能需求详述

### 5.1 模块一：打卡记录（P0）

#### 5.1.1 快速打卡（点开才展开）

**入口**：首页展示一张**折叠的引导卡**（🎀 今天捏了吗？+ 今日待记录状态），
**用户点「去打卡」后才弹出打卡表单**。首页不铺开表单，避免一进小程序就被一张大表单
挡住——首页该展示的是「今天捏了几个」的成果，不是一张待填的表。

- 表单以**底部弹层**呈现（`checkin-sheet` 组件），字段与原型 p1 一致：
  作品类型 / 捏制件数 / 作品快照 / 打卡笔记，底部是渐变主按钮
  「✨ 保存今日打卡（共 N 个）」。
- 首页入口点「去打卡」时不显示日期选择器（固定今天）；日历热力图里补录任意一天、
  作品详情页「编辑」时使用同一套表单，日期、标签、耗时等字段按场景显示。
- 字段与校验在三种入口下完全一致，避免「同一个功能两套规则」。

**字段设计**

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 打卡日期 | 日期 | 是 | 今天 | 可回溯补录，最早 3 年前，最晚今天（不允许未来） |
| 造型类型 | 单选 | 是 | 无 | `OB11娃头` / `QQ人` / `正比` / `其他` |
| 数量 | 数字 | 是 | 1 | 1–99 整数，超出需二次确认 |
| 照片 | 图片 | 否（建议） | 空 | 1–9 张，首图为封面 |
| 说明 | 文本 | 否 | 空 | ≤ 200 字 |
| 标签 | 多选 | 否 | 空 | 自定义标签，见 5.4.3 |
| 耗时（分钟） | 数字 | 否 | 空 | 用于未来效率分析 |

**交互规则**

- 造型类型以**九宫格图标 + 文字**呈现，OB11娃头、QQ人、正比 三个固定项排在第一排并带默认配色图标；`其他` 与用户自定义的品类可在「我的 → 品类管理」中增删改。
- 数量支持两种输入：**快捷加减**（- / +，步长 1）与**直接点数字输入**；常用数量（1、3、5、10）以快捷按钮形式置于底部。
- 图片上传支持从相册选择与拍摄；上传过程显示进度，支持失败重试；图片自动压缩至长边 ≤ 1200px，单张 ≤ 500KB。
- 保存成功后触发：轻震动反馈 + Toast「打卡成功，今天做了 N 个」+ 首页累计数即时 +N（乐观更新）。
- **表单未填数量不可提交**；造型未选时提交按钮置灰。

**边界与异常**

| 场景 | 处理 |
| --- | --- |
| 同一日期多次打卡 | 允许，聚合展示（如 3 条记录合并为「共 8 个」） |
| 跨日未打卡 | 首页展示「已连续 X 天未记录，今天捏了吗？」轻提示 |
| 图片上传中退出 | 后台继续上传，下次进入自动恢复并提示「有 N 张图片待完成上传」 |
| 网络异常 | 本地缓存草稿，恢复网络后自动提交 |
| 数量填 0 或负数 | 拦截并提示「数量需大于 0」 |
| 未来日期 | 不允许选择 |

#### 5.1.2 打卡记录详情

- 顶部展示封面大图（可左右滑动切换），下方展示：造型类型（带图标）、数量、日期、说明、标签、耗时。
- 若该记录含售出信息，展示「已售出 ¥XX」徽标。
- 操作：编辑、删除、复制为新记录。

#### 5.1.3 记录编辑 / 删除

- 编辑支持全部字段；**图片删除需二次确认**。
- 删除为「软删除 + 30 天回收站」，30 天内可恢复；超过自动物理删除。
- 删除后统计数字实时回滚。

### 5.2 模块二：统计（P0 / P1）

#### 5.2.1 年度总览

**入口**：首页点击「年度统计」或底部 Tab「统计」。

**内容布局（自上而下）**

1. **年度切换器**：左右箭头 + 年份下拉，默认当前年，可回溯至最早记录年。
2. **核心数字卡**（一屏内可见）
   - 今年累计：`128 个`
   - 每日平均：`1.2 个/天`（按有记录天数计）
   - 有记录天数：`86 天`
   - 制作中/未售出：`94 个`
3. **分造型数量**：横向条形图，OB11娃头 / QQ人 / 正比 / 其他，展示数量与占比。
4. **月度趋势**：12 个月柱状图，标注最高产月份。
5. **年度对比**：与上一年同口径对比（数量、增长率），用 ↑/↓ 标注。

**图表规范**

- 统一色板（分类色，颜色跟随分类实体固定分配，筛选后不重新着色）：

  | 分类 | 亮色（底色 `#FFFFFF`） | 暗色（底色 `#221B2E`） |
  | --- | --- | --- |
  | OB11娃头 | `#F68CA1`（樱花粉） | `#D46D83` |
  | QQ人 | `#55BCFA`（天空蓝） | `#2F9CD8` |
  | 正比 | `#54CB99`（薄荷绿） | `#2BAA7B` |
  | 其他 | `#C49BF3`（薰衣草紫） | `#A57CD2` |

  > 该色板经 `validate_palette.js` 双模式校验：亮度带、彩度下限、相邻色对 CVD 分离度
  > （最差 ΔE 13.3 亮 / 13.3 暗，门槛 8）、常视力分离度（最差 ΔE 16.0 亮 / 15.8 暗，门槛 15）全部通过。
  > 亮色下四色对白底都低于 3:1（2.02–2.29），因此**所有图表必须直接标注数值**（relief 规则），
  > 不得把数值只藏在 tooltip 里。用户自建分类从扩展色板 `#F7B267`/`#E88AC0`/`#7FD1A8`/`#8FB8F0` 依次取用，不循环、不生成新色相。
- 图表底色：亮 `#FFFFFF` / 暗 `#221B2E`；网格线：亮 `#F3E7EE` / 暗 `#342A42`（1px 实线，不用虚线）；
  主文字：亮 `#4A3A52` / 暗 `#F4ECF7`；次文字：亮 `#64536E` / 暗 `#D6C8E0`；弱化文字：亮 `#7C6B85` / 暗 `#94859F`。
- 文字一律使用文字色令牌，绝不穿数据色；识别身份靠文字旁的色块，不靠给文字上色。
- 柱状图/条形图数值直接标注在图元旁，不依赖 tooltip 才能读数；条形图分类名直接标在左侧。
- 每个图表都要有等价的数字读法（月度趋势提供「看数字」表格视图），保证不依赖颜色与图形也能读到全部数值。
- 空数据状态：插画占位 + 「还没有记录，去捏第一个吧」+ 跳转打卡按钮。

#### 5.2.2 月度日历热力图

- 展示某年 12 个月的日历网格，每格颜色深浅表示当日数量（0 为空白格）。
- 使用**单一色相的顺序色阶**（樱花粉，亮色 `#E5BAC1`→`#DB99A4`→`#CE7788`→`#BC586E`；
  暗色 `#5F3C42`→`#8A4F5A`→`#B76274`→`#E27A8F`），不用彩虹色阶；分 4 档，0 件为空心格。
- 点击某天 → 弹出当日记录列表，可直接跳转补录该日。
- 顶部提供年份切换与「只看有记录的日子」筛选。

#### 5.2.3 营收统计

**记录售出的两种方式**

| 方式 | 路径 | 适用场景 |
| --- | --- | --- |
| A. 打卡时直接记录 | 打卡表单展开「售出信息」区域 | 当天现做现卖 |
| B. 从作品库补录 | 作品详情 → 「标记售出」 | 库存后续卖出 |

**售出表单字段**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 售出数量 | 数字 | 是 | 默认 1，不可超过该记录未售出数量 |
| 单价（元） | 数字 | 是 | 支持小数，两位精度 |
| 售出日期 | 日期 | 是 | 默认今天 |
| 销售渠道 | 单选 | 否 | 小红书 / 闲鱼 / 微信 / 线下 / 其他 |
| 备注 | 文本 | 否 | ≤ 100 字 |

**统计输出**

- 累计营收：`¥ 3,860`
- 售出总数：`62 个`
- 未售出（库存）：`66 个`
- 单件均价：`¥ 62.3`
- 按年 / 按月的营收曲线
- 按造型的营收占比（哪类造型最赚钱）
- 按销售渠道的营收占比

**成本与利润（P2 预留）**：预留「单个成本」字段，启用后展示毛利 = 营收 − 成本×售出数、利润率。本期**只做字段预留**，不提供设置入口——品类管理里不出现成本与单价相关配置。

### 5.4 模块四：我的 / 设置（P1 / P2）

#### 5.4.1 品类管理
> 界面上统一叫「品类」；PRD 其余章节沿用「造型」这个词，指的是同一个东西。

- 内置：`OB11娃头`、`QQ人`、`正比`、`其他`（**不可删除**，可改名 / 换图标 / 调排序）
- 自定义：**可新增、编辑、删除**（删除时历史记录自动迁移到「其他」）
- 每种品类可设置：名称、图标、主题色。
- 默认单价、默认成本**本期不提供设置入口**（字段仍预留，见 §5.2 成本与利润）。售出时在售出表单里手填单价。

**规则**

- **默认的四个内置品类不做改动**：不能删（界面连删除按钮都不给），但可以改名、换图标、调顺序。
- **自定义品类最多 4 个**。颜色按实体固定：内置四个占前四个色槽，自定义品类依次用后四个（4~7），
  **固定顺序、不循环**——色槽一旦复用，某个品类的颜色就会随别人增删而变，
  年度统计里的颜色也会跟着乱。所以第 5 个直接不给建，并提示上限。
- 换图标时，用户挑的图标**优先于**内置品类默认的 svg；没动过图标就保留默认 svg。

#### 5.4.2 打卡提醒
- 开关 + 提醒时间（默认 20:00，可 15 分钟粒度）。
- 提醒文案可自定义，不做多套文案库。
- 需用户手动授权订阅消息（微信小程序模板消息），拒绝后静默关闭，不打扰。

#### 5.4.3 标签管理
- 常用标签预置：`限定配色`、`练手`、`送人`、`返工`、`急单`、`已淘汰`。
- 支持自定义新增，删除时不影响历史数据。

#### 5.4.4 数据导出与备份
- 导出格式：JSON（含全部记录与图片本地文件名）、CSV（打卡流水，便于 Excel 分析）。
- 年度报告导出为长图（可保存到相册）。

### 5.6 模块五：账号与登录（游客优先）｜P0

#### 5.6.1 设计原则：游客优先（Guest-first）

这是本模块唯一重要的一条原则，比任何字段定义都重要：

> **浏览永远不被强制登录。** 用户可以在完全未登录的状态下打开小程序、
> 查看统计、翻作品库、读年度数字。登录是一个**可选的增强**（云端备份、跨设备），
> 不是使用前提。

推论：

- 首次进入小程序**不弹全屏登录页**，不拦截任何页面。
- 任何读操作（看统计、看作品库、看热力图、看营收）**任何情况下都不要求登录**。
- **打卡要登录。** 打卡是写操作，记录要落到账号里才能跨设备同步，
  未登录时点「去打卡」直接带去登录页，**登录完接着去打卡页**，不用再点一次。
  打卡页自己也要拦（它能从首页、作品库详情、日历补录三处进入），
  免得绕过首页入口。
- **素材库要登录。** 它是用户的私有内容，未登录时一律按空处理（§5.7）。
- 只有**确实需要账号态**的功能才强制登录，且强制时必须给出「为什么需要」的解释，
  并始终提供「暂不登录」出口（登录页的「先随便看看」）。
- 售出目前仍不强制登录——**待定**：若售出也要同步到账号，则同样应登录后才行。

#### 5.6.2 账号模型：注册是隐式的

微信小程序没有「注册」表单。用户在登录页点击一次按钮即完成「注册 + 登录」：

| 步骤 | 客户端 | 服务端 |
| --- | --- | --- |
| 1 | `wx.login()` 拿到临时 `code`（5 分钟内有效，一次性） | — |
| 2 | `code` 发送到自有服务端 | 用 `code` 调 `jscode2session` 换 `openid` / `session_key` |
| 3 | — | `openid` 不存在则**自动创建账号**并初始化空数据；存在则返回已有数据 |
| 4 | 拿到自己的 `token` 与账号信息，存入本地 | 签发 `token` |

**不采集手机号、不要求填资料。** 昵称与头像是可选的补充信息：

- 昵称：`<input type="nickname">` 组件（用户手动输入或选择微信昵称）
- 头像：`<button open-type="chooseAvatar">` 组件（用户主动点击才拉起微信头像选择）

这两个组件都由用户主动触发，**不使用已被回收的 `wx.getUserProfile`**。
用户跳过这两项，账号依然可用，只是一个没有头像昵称的账号。

**服务端接口契约**

| 接口 | 入参 | 返回 |
| --- | --- | --- |
| `POST /api/login` | `{ code, nickname?, avatarUrl? }` | `{ token, account: { openid, unionid, nickname, avatarUrl, createdAt }, newUser, expireSeconds, mock }` |
| `GET /api/profile` | — | `{ account, mock }` |
| `POST /api/profile` | `{ nickname, avatarUrl }` | `{ account, mock }` |
| `POST /api/sync/push` | `{ deviceId, records, sales, shapes, tags, photos }` | `{ serverTime, merged }` |
| `POST /api/sync/pull` | `?since=…` | `{ serverTime, records, sales, photos }` |
| `POST /api/account/delete` | — | `{ deleted: true }` |

> `token` 走请求头 `Authorization: Bearer <token>`，不放 body。
> 服务端只存 `openid`（与 `unionid`），不存 `session_key`；`token` 自签并可撤销。
> 记录归属以 `openid` 为准，客户端本地 `deviceId` 只用于冲突合并。

**关于昵称头像随登录一起提交**

`POST /api/login` 除 `code` 外还接受可选的 `nickname` / `avatarUrl`。
这两个字段**不是微信给的**——`jscode2session` 只返回 `openid` / `session_key` / `unionid`，
昵称与头像只能由用户在小程序的 `<input type="nickname">` 与
`<button open-type="chooseAvatar">` 里主动触发。放在同一次登录请求里，
是为了避免「登录成功但昵称没存上」——补一次 `POST /api/profile` 是第二次请求，
它失败就只剩一个没有昵称的空账号。用户跳过这两项时，账号依然可用。

**`mock` 标记**

服务端未配置小程序 `appid` / `secret` 时，只能用 `md5(code)` 当 `openid`——
此时返回的 `mock` 为 `true`。客户端据此提示用户「当前是本地联调模式，
登录拿到的是模拟账号，不是你的真实微信号」，避免用户去数据库里找自己的账号而找不到。
后端补齐 `appid` / `secret` 后，`mock` 变为 `false`；客户端启动时拉一次
`GET /api/profile` 同步这个状态。

#### 5.6.3 状态机

```
              ┌──────────────────────────────────────┐
              │                                      │
  未登录 ──跳过──▶ 游客模式（本地） ──登录──▶ 已登录（账号 + 本地）
              │                          ▲                │
              └──────退出登录──────────────┘◀────退出──────┘
```

| 状态 | 数据存放 | 能力 |
| --- | --- | --- |
| 未登录 | 本地 | 全部本地功能 |
| 游客模式 | 本地 | 全部本地功能；标记「已跳过登录」，不再重复引导 |
| 已登录 | 本地 + 云端 | 本地功能 + 云端备份 + 跨设备同步 |

**游客模式与未登录的区别只有一个**：游客模式记录了「用户已经做过选择」，
之后不再反复弹引导。未登录且未选择过引导的访客，第一次进入首页时展示一条可关闭的引导条。

#### 5.6.4 登录引导的出现时机

| 场景 | 是否提示 | 形式 |
| --- | --- | --- |
| 首次进入首页（未登录、未选择过） | 提示一次 | 首页顶部**可关闭的引导条**，不遮挡内容 |
| 浏览统计 / 作品库 / 热力图 | **永不提示** | — |
| 打卡 / 编辑 / 记录售出 | **永不提示** | — |
| 用户主动点「我的 → 登录」 | — | 进入登录页 |
| 本地数据即将写满（> 8MB） | 提示一次 | 引导登录以获得云端备份 |
| 用户手动点「开启云端备份」 | — | 进入登录页 |
| 未来的社区发布 / 分享作品 | 强制 | 弹登录页，并说明「发布需要身份」 |

引导条文案：
> **登录后云端备份，换手机不丢记录** 　[登录] [×]

**不做的事**：不做启动时全屏登录遮罩、不做「必须登录才能看」的空状态、
不做每 3 次操作弹一次的打断式引导。

```
┌─────────────────────────────┐
│         捏土打卡              │
│      让记录跟着你走            │
│                             │
│      ┌───────────┐          │
│      │   头像选择  │          │  ← button open-type="chooseAvatar"
│      └───────────┘          │
│      昵称（选填）              │  ← input type="nickname"
│                             │
│   ┌─────────────────────┐   │
│   │    微信一键登录       │   │  ← wx.login() → code → 服务端换 token
│   └─────────────────────┘   │
│                             │
│      先随便看看 ›             │  ← 跳过，标记游客模式，返回上一页
│                             │
│   登录即表示同意《用户协议》   │
│   与《隐私政策》              │
└─────────────────────────────┘
```

**交互细节**

- 「微信一键登录」按钮：点击后按钮进入 loading，文案变为「登录中…」；成功后跳转回来源页；
  失败按类型给出不同提示：
  - 后端未配置 / 网络错误 → 「登录服务暂时不可用，你仍然可以先记录」+ 自动切回游客态
  - 用户拒绝授权 → 不弹系统授权框（`wx.login` 不需要用户确认），仅在服务端异常时提示
  - 账号被注销 → 提示「该账号已注销，请重新登录」
- 「先随便看看」：直接返回来源页并把状态置为游客模式。**该按钮在登录页任何状态下都可用**，
  包括加载失败时——不把用户堵死在登录页。
- 登录成功后若本地已有记录，进入 §5.6.6 的数据归属选择。

#### 5.6.6 登录后的本地数据归属

登录时本地可能已有大量记录，必须明确它们去哪。默认**合并**：

| 选项 | 行为 | 适用 |
| --- | --- | --- |
| **合并到账号（默认）** | 本地记录上传到云端，云端已有记录拉下来合并；同一条以 `updatedAt` 较新者为准 | 游客用了几天再登录 |
| 仅使用云端数据 | 丢弃本地未上传的记录，仅拉取云端数据 | 换机后在新设备登录 |
| 暂不处理 | 保持本地，登录只用于备份身份 | 用户想自己决定 |

- 合并是**幂等**的：重复登录不会产生重复记录（按记录 `id` 去重）。
- 照片同步在 V1.1 随对象存储一起做，V1.0 先同步记录与售出的元数据。
- 合并期间显示进度，完成后给一行结果提示：「已合并 128 条记录」。

#### 5.6.7 退出登录与注销

| 操作 | 行为 | 数据 |
| --- | --- | --- |
| 退出登录 | 回到游客模式 | 本地数据**保留**，不清空 |
| 退出并清除本地数据 | 先弹二次确认，说明不可恢复 | 清空本机记录，云端数据保留 |
| 注销账号 | 调 `/api/account/delete`，服务端删除该 `openid` 的全部数据 | 本地数据清空 |

- 退出登录**不删除**任何本地记录——这是用户最容易被吓到的地方，文案要写明。
- 注销账号是合规要求（个人信息删除权），入口放在「我的 → 账号设置」底部，
  需要二次确认 + 输入确认文案。

#### 5.6.8 我的页账号卡片

| 状态 | 卡片内容 |
| --- | --- |
| 游客 | 「未登录 · 数据只存在这台设备上」+ 按钮「登录 / 注册」+ 说明「登录后自动备份，换手机不丢」 |
| 已登录 | 头像 + 昵称 + 「微信账号已绑定」+ 入口「账号设置」 |

### 5.7 模块六：素材库（P1）

#### 5.7.1 定位

素材库存的是**素材图**，和打卡记录是两类东西：

| | 打卡记录 | 素材库 |
| --- | --- | --- |
| 内容 | 一次做出来的成品（带数量、日期、造型） | 一张张参考图 / 素材图 |
| 用途 | 记录产量与营收 | 备料、找配色、留灵感 |
| 组织 | 按造型分类 + 日期 | 按**文件夹**自由分组 |

常见内容：想要的配色参考、买到的粘土包装、工具照片、教程截图、某个角色的细节图。
这些图**不属于某一次打卡**，用日期组织没有意义，所以单独做一个按文件夹管理的素材库。

**可见性：素材库是用户的私有内容，只有登录后才能看到。**

- 未登录时，素材库首页、文件夹列表、素材详情一律按「空」处理：
  不显示任何文件夹、素材、数量与预览图
- 未登录时也不提供新增入口（新建文件夹 / 添加素材）——
  否则用户加了素材却看不到，会以为东西丢了
- 退出登录后素材库重新变空，但**本机数据一条不删**（§5.6.4），
  再次登录即可恢复可见
- 「我的」页的素材数量与预览图同样受这条约束，未登录时显示「登录后可见」

> 打卡记录与售出不受此约束：它们在游客模式下照常可写可看（§5.6.1）。

#### 5.7.2 文件夹

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 主键 |
| name | string | 文件夹名，≤ 20 字 |
| cover_material_id | string | 封面素材，默认取该文件夹第一张图 |
| sort | int | 排序 |
| created_at | datetime | — |
| deleted_at | datetime | 软删除 |

**规则**

- 文件夹只有一层，不做嵌套（个人素材量级不需要，嵌套会让查找更慢）。
- 删除文件夹**不删素材**：素材自动转为「未分类」，避免误删丢图。
- 内置一个虚拟的「未分类」分组（不是真的文件夹），收纳没有归类或原文件夹被删的素材。
  没有未分类素材时这个分组不显示。

#### 5.7.3 素材

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 主键 |
| folder_id | string | 所属文件夹，空字符串表示未分类 |
| url | string | 图片地址（本地持久化路径） |
| name | string | 名称，默认「素材 N」，≤ 30 字 |
| note | string | 备注，≤ 100 字 |

#### 5.7.4 交互

**素材库首页**（`/pages/material/index`）两个分组：

- **文件夹**：网格展示文件夹卡片（封面图 + 名称 + 素材数），右上角「新建文件夹」。
  顶部固定一个「全部素材」入口，下方按需显示「未分类」。
- **全部素材**：所有素材的缩略图网格，按添加时间倒序，顶部有名称搜索框。

| 操作 | 交互 |
| --- | --- |
| 新建文件夹 | 输入名称 → 创建，落在网格末尾 |
| 重命名文件夹 | 文件夹详情页顶部「编辑」 |

| 素材改名 / 加备注 | 素材详情页 |
| 移动素材 | 素材详情页「移动到文件夹」，选择目标文件夹或未分类 |
| 删除素材 | 二次确认，**软删除进回收站**（与打卡记录同一套 30 天机制） |

**素材详情页**（`/pages/material/detail`）：大图 + 名称 + 备注 + 所属文件夹 + 操作。

#### 5.7.5 入口

「我的」页新增一项：**素材库**（图标 📁），副标题显示文件夹数与素材数。

### 6.3 关键统计口径定义（避免歧义）

| 指标 | 口径 |
| --- | --- |
| 累计产量 | 满足 `status = normal` 的所有记录的 `count` 之和 |
| 售出数量 | 所有 `sale.quantity` 之和 |
| 未售出数量 | 累计产量 − 售出数量（**负数时按 0 显示并给出提示**） |
| 营收 | 所有 `sale.total_amount` 之和（**按售出日期归属到对应年/月**，而非按打卡日期） |
| 每日平均 | 累计产量 ÷ 有记录的天数（不是 ÷ 全年天数）；口径在 UI 上注明 |
| 产量归属 | 产量归属于**打卡日期**所在年/月 |

> **重要**：营收与产量的时间归属规则不同（产量按打卡日、营收按售出日），这是最容易出错的地方，需在开发与测试中重点验证。

| 首屏渲染 | ≤ 800ms |

| 图片本地缓存 | 缩略图缓存 7 天，清理需用户确认 |

### 8.2 可靠性

- 数据本地优先存储（SQLite / Storage），**先写本地再同步云端**，弱网可离线打卡。
- 本地每日自动备份一份 JSON 到沙盒，保留最近 7 份。
- 云端同步冲突策略：以 `updated_at` 时间戳 + 字段级合并，售出记录为追加型不做覆盖。
- 目标可用性 99.5%。

### 8.3 视觉风格：二次元可爱风（樱花马卡龙）

整体视觉走**二次元可爱风**，基调是奶油底 + 樱粉/薰衣草马卡龙色 + 大圆角 + 圆润阴影。

> **视觉规范的唯一来源**：`003.前端代码/frontend/sakura_clay_studio/DESIGN.md`（Stitch 生成的设计系统）
> 与 `003.前端代码/frontend/p*/screen.png`（四张原型截图）。
> 改动界面时以它们为准；实现层的落地规则见下表与 `styles/theme.wxss`。
> 代码里的所有色值都必须来自 `styles/theme.wxss` 的 CSS 变量——
> `test/style.test.js` 会检查页面/组件样式里有没有写死颜色。

### 8.4 体验与合规

- 支持深色模式（跟随系统），图表色板在深色下有对应变体。
- 所有交互元素点击区域 ≥ 44×44pt。
- 首启需隐私政策授权，说明「照片仅存储于用户自己的账号空间，不用于公开展示，除用户主动分享外不会公开」。
- 支付相关：本产品不收款，不涉及资金流转，无需接入支付牌照；若未来接入分销，需重新评估。

**账号与登录的合规约束**

- 首次进入**不弹隐私授权**（不采集任何信息，无需授权）。隐私政策以「可随时查阅」的方式提供，
  用户点登录时才展示并要求勾选同意。
- `wx.login` 不产生用户授权弹窗，因此**浏览全程零授权打扰**。
- 头像昵称走 `chooseAvatar` / `type="nickname"` 组件，由用户主动点击触发；
  不使用已回收的 `wx.getUserProfile`。
- 游客模式下**不采集任何身份信息**，仅在本机生成一个随机 `device_id` 用于数据合并。
- 必须提供账号注销入口（个人信息删除权），且注销需二次确认。
- 服务端不存储 `session_key`，不采集手机号，不做实名。

### 8.5 兼容性

- 微信版本 ≥ 8.0，基础库 ≥ 2.20.0（`chooseAvatar` 需基础库 ≥ 2.21.2）
- iOS 14+ / Android 9+
- 适配 iPhone X 类刘海屏、底部安全区

## 十二、验收标准（Acceptance Criteria）

### AC-1 快速打卡
- 在首页选择「QQ人」，数量调为 3，上传 2 张照片，点击保存 → 2 秒内首页累计数增加 3，记录出现在「最近记录」首位。
- 数量为 0 时保存按钮不可点击。
- 选择今天以外的日期可正常保存，记录归入该日期对应的年/月统计。

### AC-2 年度统计正确性
- 造 3 条数据：2026-01-05 QQ人 5 个；2026-03-10 OB11娃头 2 个（1 个售出于 2026-05-01，¥30）；2025-12-31 正比 1 个。
- 打开 2026 年统计：累计产量 = 7；QQ人 = 5，OB11娃头 = 2；分类占比 71% / 29%。
- 打开 2025 年统计：累计产量 = 1，正比 = 1。
- 打开 2026 营收：售出 1 个，营收 = ¥30（归属 2026-05）；未售出 = 6。

### AC-3 售出上限
- 对一条 count = 2 的记录标记售出 3 个 → 表单拦截并提示「不能超过该记录的未售出数量（2）」。

### AC-4 编辑回滚
- 删除一条 count = 5 的记录 → 累计数立即减少 5；30 天内从回收站恢复 → 累计数恢复为原值，统计同步。

### AC-5 离线可用
- 断网状态下完成打卡并保存 → 提示「已保存，联网后自动同步」；恢复网络后自动上传，图片无丢失。

### AC-6 空状态
- 新用户首次进入统计页 → 显示空状态插画与引导按钮，不出现 `NaN`、空白图表或报错。

### AC-7 深色模式
- 系统切换深色模式后，首页与统计页所有文字、图表、卡片背景对比度 ≥ 4.5:1，无白底白字。

### AC-8 游客模式可用性
- 未登录、未点「跳过」的新用户进入小程序 → **不出现任何登录遮罩**，
  首页展示一条可关闭的登录引导条，统计 / 作品库 / 日历 / 营收全部可正常浏览。
- 未登录时点首页「去打卡」→ **被带到登录页**（不是弹窗，不是拦截遮罩），
  登录成功后**直接进入打卡页**，不用再点一次「去打卡」。
- 打卡页被直接打开（作品库详情 / 日历补录）→ 同样先带去登录，
  登录完回到打卡页且**保留原来的参数**（编辑哪条、补哪天）。
- 本地已有的历史记录在退出登录后仍然保留，年度统计数字正确。

### AC-9 跳过选项
- 登录页点「先随便看看」→ 立即返回来源页，状态变为游客模式，
  首页引导条不再出现；「我的」页账号卡片显示「未登录 · 数据只存在这台设备上」。
- 登录页在**加载失败 / 后端未配置**时，「先随便看看」依然可用（不能把用户堵死在登录页）。

### AC-10 登录后数据不丢
- 游客模式下积累 5 条记录 → 登录成功 → 默认合并 → 本地 5 条记录全部保留，
  统计数字与登录前一致；重复登录一次，记录数不变（幂等，不产生重复）。
- 合并完成后提示「已合并 N 条记录」。

### AC-11 退出与注销
- 已登录状态下点「退出登录」→ 回到游客模式，**本地记录一条不少**（数量与退出前一致），
  仅清掉账号态。
- 点「注销账号」→ 二次确认后，服务端数据与本地数据均被清除，
  账号卡片回到游客态。

### AC-12 浏览不被强制
- 依次打开统计 / 作品库 / 日历 / 营收 / 作品详情 / 我的 → **任何一个页面都不弹登录**。
- 未登录状态下点「打卡」「编辑」「记录售出」→ 全部正常完成，不弹登录。

### AC-13 素材库文件夹
- 新建文件夹「配色参考」→ 网格出现该文件夹，封面为空、计数为 0。
- 往该文件夹添加 3 张素材 → 封面自动显示第一张，计数变为 3。
- 删除该文件夹 → 二次确认后文件夹消失，**3 张素材全部转到「未分类」，一张都没少**。

### AC-14 素材增删改查
- 添加 5 张素材 → 「全部素材」计数为 5，按添加时间倒序。
- 素材改名「暖橘色」→ 列表与详情都显示新名字。
- 把素材移到另一个文件夹 → 目标文件夹计数 +1，原文件夹计数 −1，素材本身不重复。
- 删除素材 → 二次确认后从列表消失，进回收站。

### AC-15 素材搜索
- 素材库「全部素材」输入「橘」→ 只剩名称含「橘」的素材；清空输入 → 恢复全部。
