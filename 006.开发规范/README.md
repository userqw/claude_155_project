# 006 · 开发规范

本目录是「捏土打卡」各端的开发规范。规范面向**人**，不是面向工具——
它假设你想把事情做对，只是不想在每件事上重新想一遍该怎么做。

## 目录

| 文件 | 内容 |
| --- | --- |
| [Java开发规范.md](Java开发规范.md) | Java / Spring Boot 后端规范（分层、命名、异常、日志、接口、数据库、事务并发、配置安全、测试、禁止事项、评审清单） |

## 为什么写成这样

规范最容易变成一堆正确但没用的废话。这里做了三件事：

1. **每条规则有编号**（`DB-04`、`ERR-02`），评审和 PR 里可以直接引用，不用复述全文。
2. **分级**（P0 强制 / P1 应当 / P2 建议），让人知道哪些必须改、哪些可以商量。
3. **例子来自这个仓库真实的坑**——复合主键漏了 `openid` 会查串账号、
   `catchtap` 写成 `onClose` 会让弹层一打字就收起、
   `wx.env` 在低版本基础库上是 `undefined` 会抛「undefined is not an object」。
   抽象的规则记不住，具体的坑记得住。

## 适用范围

- **强制**：`005.后端代码/` 及后续所有 Java 服务。
- **参考**：其他端（小程序前端、SQL 脚本）的约定散在各自目录与根目录的 `CLAUDE.md` 里。

存量代码不要求立刻整改，但**改到哪一行，那一行就要符合**（改一行算一行）。

## 怎么用

- **写代码前**：扫一眼对应章节，特别是 P0 清单。
- **提 PR 前**：过一遍第 12 章的评审清单。
- **评审时**：按编号给意见，例如「违反 DB-04」。
- **有异议**：改这份文档并提 PR，不要在代码里"事实上"改规矩。
